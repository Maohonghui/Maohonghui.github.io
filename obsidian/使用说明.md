# 手机 Obsidian 使用说明

> 这份文档讲两件事：**怎么发博客文章** 和 **怎么打卡早睡**。
> 两个流程都只需要在手机上操作，不需要碰电脑，也不需要跑任何脚本。

---

# 第一部分：手机需要装什么

## 已经装好的（我确认过你电脑上的库）

| 插件 | 状态 | 用途 |
| --- | --- | --- |
| **Templater** | ✅ 已装 | 自动填日期、生成打卡清单 |
| **Heatmap Tracker** | ✅ 已装 | 在 Obsidian 里也能看热力图 |
| **Periodic Notes** | ✅ 已装 | daily note |
| **Dataview** | ✅ 已装 | Heatmap Tracker 依赖它 |
| **Remotely Save** | ✅ 已装 | 库的备份同步 |

## 手机还必须装一个

| 插件 | 用途 |
| --- | --- |
| **GitHub Publisher**（或它的新版 **Enveloppe**） | 把笔记推到博客仓库 |

你说你已经配好了 GitHub Publisher，那这一步应该已经完成了。
如果手机上是全新的库，需要装它并按下文配置。

> ⚠️ **手机上不需要装 Git 插件**（比如 obsidian-git）。GitHub Publisher 自己就能推送。

# 第二部分：发博客文章

## 一次性设置

### 1. Templater 的模板文件夹

设置 → **Templater** → `Template folder location` = `记录/Templates`

我已经把两个模板放进这个文件夹了，电脑上打开 Obsidian 就能看到：

- `博客文章模板.md`
- `早睡打卡生成模板.md`

> 手机和电脑共用一个库（通过 Remotely Save 同步），所以电脑上放好，
> 同步之后手机上也会有。如果手机上还没有，先手动同步一次。

### 2. 附件（图片）存放位置

设置 → **文件与链接** → `新附件的默认存放路径` → 「在下面指定的文件夹中」 → 填：

```
assets/img/posts
```

### 3. GitHub Publisher 设置

| 设置项 | 填什么 |
| --- | --- |
| Repository | `Maohonghui/Maohonghui.github.io` |
| Branch | `main` |
| GitHub token | 需要一个有 **Contents 读写** 权限的 token（见文末） |
| File path / Default folder | `_posts` |
| 图片 / 附件文件夹 | `assets/img/posts` |
| Use post type subdirectories | **Off** |

## 发一篇文章

1. 新建笔记，文件名起成 `2026-10-08-我的标题` 这种
   （日期前缀是给 Jekyll 认的，后面的字会变成网址 `/posts/我的标题/`）
2. 插入模板：命令面板 → `Templater: Insert template` → 选「博客文章模板」
3. **日期会自动填好**，你只需要填这几项：

   ```yaml
   title: "我的标题"
   categories:
     - 随笔
   tags:
     - 日常
   description: "显示在卡片上的小字"
   ```

4. 正文随便写。要插图就直接把图片粘进来。
5. 发布：命令面板 → `Upload single current active note`

**大概 1～2 分钟后**网站自动更新。

### 加封面图

把图片拖进笔记后，把 Front Matter 的 image 改成：

```yaml
image:
  path: /assets/img/posts/图片名.jpg
  alt: "封面说明"
```

不要封面就保持 `path: ""`，这样最安全。

> ⚠️ **不要设 `media_subpath`**（模板里默认是空的，别改它）。
> 它会被主题拼在图片路径前面，而上面的路径已经是以 `/` 开头的绝对路径，
> 填了就会变成 `/assets/img/posts/assets/img/posts/xxx.jpg`，直接 404 裂图。

# 第三部分：早睡打卡（重点）

## 设计目标

**你每天只需要做一个动作：点一下方框。**

具体来说：

1. 打开「早睡打卡」这篇笔记
2. 滑到最下面（今天在最后）
3. 点一下 `- [ ] 2026-10-08` 这个方框，它变成 `- [x] 2026-10-08`
4. 发布

就这样。没有脚本，没有转换，不用开电脑。

## 清单在哪儿

我已经在你的库里建好了：**`早睡打卡.md`**（库的根目录）

里面从今天到今年年底，每天一行，长这样：

```markdown
# 早睡打卡

- [ ] 2026-10-08   ← 今天
- [ ] 2026-10-09
- [ ] 2026-10-10
...
```

## 每天怎么做

| 步骤 | 操作 | 耗时 |
| --- | --- | --- |
| 1 | 打开 `早睡打卡.md` | 1 秒 |
| 2 | 滑到底部 | 1 秒 |
| 3 | 点一下当天的方框 | 1 秒 |
| 4 | 命令面板 → `Upload single current active note` | 3 秒 |

想记录具体几点睡、几点起，可以在日期后面加时间
（**可选**，不加也完全能用）：

```markdown
- [x] 2026-10-08 23:05 07:30
```

第一个时间是入睡，第二个是起床。填了之后，博客上鼠标悬停能看到。

## 想一次性生成明年的清单

清单用完了（或者你想提前生成明年一整年）时：

1. 打开 `早睡打卡.md`
2. 命令面板 → `Templater: Replace templates in the active file`
3. 它会自动从**今天**补到**今年 12 月 31 日**

已经打过的勾不会被动到，重复运行也不会插入重复行。

> 换年份的时候，手动在下面加一行 `## 2027` 之类的标题，再跑一次模板即可。

## 博客上怎么看

打开博客左侧栏的 **「早睡」** 页面：

- 🟩 **绿色** = 那天 23:00 前睡了
- 🟥 **红色** = 有打卡但没早睡
- ⬜ **浅灰** = 那天没打卡（不代表没早睡，只是没记）

页面上还有早睡率、当前连续、最长连续等数字。

## 判定规则

| 你写的内容 | 博客怎么算 |
| --- | --- |
| `- [x] 2026-10-08 23:05 07:30` | 23:05 > 23:00 → **没早睡** |
| `- [x] 2026-10-08 22:40` | 22:40 ≤ 23:00 → **早睡** |
| `- [x] 2026-10-08`（只打勾不写时间） | 直接算 **早睡** |
| `- [ ] 2026-10-08`（没打勾） | **没记录**，格子留空 |

**几点算早睡**可以改：编辑博客仓库的 `_config.yml`：

```yaml
sleep_log:
  threshold: "23:00"    # 想改成 22:30 就写 "22:30"
  days: 91              # 热力图显示多少天
```

> 跨过午夜的时间会自动处理：`01:30` 会被当成"比 23:00 晚"，不会被误判成早睡。

# 第五部分：常见问题

### Q：打卡笔记发布到哪里？

它会成为博客仓库根目录的 `sleep-log.md`。
（博客构建时会自动读取它，这一步不需要你操心。）

> 如果你的 Publisher 只能发到 `_posts`，那就把 Publisher 里这篇笔记的
> 目标路径单独改成仓库根目录，文件名保持 `sleep-log`。
> 实在改不了也没关系 —— 告诉我，我给你换个方案。

### Q：打卡笔记要不要加 Front Matter？

**不需要，也不要加。** 它就是一个普通的复选框清单。
博客是用正则去读 `- [x] 日期` 这种行的，加了 Front Matter 也不影响，
但完全没必要。

### Q：博客上热力图是空的？

依次检查：

1. `早睡打卡.md` 里有没有 `- [x] 2026-10-08` 这样**打勾**的行
2. 这篇笔记有没有真的发布成功（去 GitHub 仓库看根目录有没有 `sleep-log.md`）
3. 博客的 Actions 页面有没有构建成功

### Q：文章发布后网站还是旧的？

等 1～2 分钟。之前的 Service Worker 缓存问题已经修掉了，
现在不需要再手动 Ctrl+F5。

### Q：图片显示不出来（裂图）？

检查路径是不是**全小写**、是不是以 `/assets/img/posts/` 开头，
以及仓库 `assets/img/posts/` 里确实有那个文件。

因为博客跑在 Linux 上，**文件名区分大小写**：
手机上叫 `JPEG_abc.JPG`，上传后变成 `jpeg_abc.jpg`，文章里写大写就会 404。

# 附：GitHub Token 怎么弄

Publisher 需要一个能写仓库的 token。

1. 打开 https://github.com/settings/personal-access-tokens/new
2. **Token name**：随便，比如 `obsidian-blog`
3. **Expiration**：建议 90 天（到期再换一个）
4. **Repository access** → `Only select repositories` → 选 `Maohonghui.github.io`
5. **Permissions** → 展开 `Repository permissions` → 找到 **Contents** → 选 **Read and write**
   （这是**唯一**需要开的权限，其他都不用动）
6. 生成后复制那串 `github_pat_...`，粘到 Publisher 设置里

> ⚠️ 你现在用的那个 token 只有**只读**权限，所以推送会失败并报
> `Resource not accessible by personal access token`。
> 按上面第 5 步把 Contents 改成 **Read and write** 就好了。
